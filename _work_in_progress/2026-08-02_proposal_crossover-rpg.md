## 1. コンセプト

百花繚乱研究所の全創作タイトルを、各タイトルのストーリーを「イベントストーリー（章）」として踏まえたうえで一つに束ねる**買い切り型クロスオーバーRPG**。運営型（ソシャゲ）を避け、以下の二層で展開する。

- **Phase A: TRPGシステム＋シナリオモジュール集**（同人頒布・運営コストゼロ）
- **Phase B: Unity製オムニバスRPG**（買い切り＋章別無料アップデート）

Phase A のモジュールが Phase B の脚本・バランス検証を兼ねる。

### 世界観上の正当化 — 三層構造（既存設定のみで成立）

各タイトルは**同一世界線にあるとは限らない**。運命線探偵78の基本資料に「アルカナはたいてい複数の"岐路(ブランチ)"に跨って存在している」「基底岐路(KERNEL-BRANCH)は78枚のアルカナムスペックのすべてが共存可能な移動型の特殊な岐路」とあり（`Works_FLInvestigator78/References/ref_Reference.json` / `ref_Vocabulary.json`）、`AnotherRegions_DBLink`（異空岐路存在）はまさに岐路違いの同一存在を結ぶリンクである。これを正当化の主軸に据える。

| 層 | 内容 | 使い方 | 根拠 |
|---|---|---|---|
| 主フレーム（作中） | **岐路(ブランチ)横断**。各タイトル＝並行する岐路群。基底岐路 KERNEL-BRANCH が「全能力・全存在が共存できる唯一の岐路」としてクロスオーバー拠点を公式設定のまま担う | ハブ拠点・章移動（岐路ダイブ）・全編 | FL78 `ref_Reference.json`（アルカナムスペック）、`ref_Vocabulary.json`（基底岐路） |
| 演出（作中） | ユニバイト・ユニバースの「コードインフィニティ」製シミュレータという体裁を UI・メニュー演出に借用 | 任意（メニュー・リザルト画面等） | `Works_UnibyteLive/References/ref_Vocabulary.json` |
| 最外殻（メタ・限定使用） | **アトリエは第8界に属さない「創作世界と現実世界の中間空間」**。常設ハブには使わず、真エンディング・周回特典など一度きりの演出に温存する（候補） | 終盤・特典のみ | `Works_DestinyFoxRecords/References/ref_Reference.json` ＋ User 補足（2026-08-02） |

**スコープ制約**: フィジカル9 が触れる第1界〜第7界は、構想上ラジアン（柏木主税）以外の「創造主」が管理する世界であるため、**本ゲームの舞台・題材にはしない**。名前レベルの言及・カメオも User の個別承認を必須とする（§8）。アークナイツが他者領域の描写に節度を保つのと同じ距離感を維持する。

## 2. 先行事例分析: アークナイツ／アークナイツ：エンドフィールド（GRYPHLINE）

参照理由: 多数の陣営・地域を抱える共通舞台設定（テラ）を、章単位のフィーチャー構造と陣営演出で破綻なく積み上げている先行例。エンドフィールドは同一世界の別時代（約100年後）・別大陸（タロII）に独立した進入点を作る手法の実例（2026-01-22 サービス開始、3Dリアルタイム戦略RPG）。

## 3. 物語構成案

### メイン軸（縦糸）— 「年表」から「岐路群を跨ぐ脅威」へ

創世期年表（WDP.VII → WDC.VIII → WDP.VIII）は**基底時間軸の参考情報**とし、縦糸そのものは次で定義する（候補提示）。

- **脅威の統一**: 未来消失は「最悪の場合、"岐路(ブランチ)"そのものが世界の歴史から消失する」現象（FL78 `ref_Reference.json`）。つまり**各タイトル＝各岐路が丸ごと消される危機**が、全タイトルを横断する動機として公式設定から直接導ける。章を跨ぐ理由づけに新規設定が要らない。
- **共通敵**: **財前小里／終藤こさと**（豹変系女子NW・『破壊主』代理人）。「夜月機関・運命線探偵・獣爾騎兵などへ牙を向く」と明記済みで、『第8の世界破壊』の収束コメントと「『第9の世界破壊』というエンターテインメントのための、最高の舞台が用意されている」という台詞（`References/ref_Society.json`）が、そのままゲームの引きになる。
- **最終章の題材**: 『第9の世界破壊』は現状どの作品DBにも年代・内容が紐づいていない空席。**「岐路群の一斉消失／強制収束」級の事件**として使える唯一の枠（内容の確定は User の正典判断・§8）。

### 岐路構造がゲームにもたらす利点

1. **キャラの「別バージョン」実装が公式準拠になる**: `AnotherRegions_DBLink` の岐路違い同一存在（零 零の NT版/SCG版/UL版、錦野姉妹の FL78版/NT版など14組以上）を、そのまま別性能のプレイアブルバリエーションにできる。版権クロスオーバーゲームが言い訳に苦労する部分が、このDBでは最初から設定側にある。
2. **矛盾の吸収装置**: 年代・設定の食い違いは「別岐路」で説明可能。章ごとの独立性（P1）が世界観レベルで保証される。
3. **章選択＝岐路ダイブ**: エピソード選択式の順不同解放を、メタ演出に頼らず作中論理（基底岐路からのダイブ）で正当化できる。
4. **TRPG（Phase A）との整合**: 卓ごとに展開が分岐しても「その卓の岐路」として公式に包含できる。リプレイと正史の衝突問題が構造的に消える。

- 第2章と第3章（先代編）は年代が完全一致（2044–46、世界創造と世界破壊の表裏）。**同一事件を別視点で描く前後編**にすると、アークナイツのメイン章⇔サイドストーリー相互参照の快感を再現できる。

### プレイ順の設計

素材成熟度順（NT→FL78→獣爾→…）と物語時系列（獣爾→FL78→…→NT）が逆転している。→ **エピソード選択式（ライブアライブ／オクトパストラベラー方式）**で章を順不同解放にすれば、開発順とリリース順を物語に縛られず決められる。序章（アトリエ）が章選択ハブを世界観的に正当化する。

## 5. Phase A: TRPGシステム＋シナリオモジュール集

- **形態**: オリジナル軽量システム（判定は 6軸×ランクの2d10 程度を想定）のルールブックPDF＋章別シナリオモジュール。BOOTH 頒布＋ココフォリア用素材（駒画像は既存 Images/VRM スクショを流用）。
- **モジュール＝章マップの1行**。1本目は素材が揃う「獣爾騎兵」（P5: 独立進入点・7キャラで卓が組みやすい）か「ナンバーテールズ」（最成熟）を推奨。
- hideText を秘匿ハンドアウトに、SafetyLevel を暴走表に、Relation を PC間関係表にそのまま変換。
- **役割**: 各章のプロット・NPC・戦闘バランスの実地検証。プレイレポは SNS 小出し公開の文化とも噛み合う。
- 副次創作ガイドライン（`guideline.md`）に「TRPGセッション・リプレイ動画」の扱いを追記する必要あり → User 決定事項。

## 6. Phase B: Unity製オムニバスRPG

- **開発環境**: Unity ＋ Claude Desktop（Cowork）の Unity MCP 連携。スクリプト生成・シーン構築・アセット検証をこのセッション系列から直接操作できるため、個人開発のボトルネック（実装量）を大幅圧縮できる。
- **ビュー**: 2D〜2.5D（HD-2D風）。VRM 資産（NT は `VRMs/` あり）を 3D 化に使うか、ドット絵に落とすかは章演出方針と合わせて決定。
- **戦闘**: 共通基盤（§4）のコマンド式 or 軽量タクティクス。章固有メカニクスは「章の間だけ追加されるサブシステム」として実装（ライブアライブ方式）。
- **リリース**: Steam＋BOOTH/itch.io、買い切り。アーリーアクセスで序章＋1章から開始し、章を無料アップデートで追加（P6）。章追加のタイミングを各タイトルの DB 公開（released 化）と同期させれば、「ゲームでの登場＝実質初公開」を公式の初出イベントとして演出できる。
- **辞典連携**: ゲーム内辞典は DB の JSON から自動生成（`Localization/` の対訳資産で日英同時対応も視野）。
