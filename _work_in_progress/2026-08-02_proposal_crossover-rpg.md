## 1. コンセプト

百花繚乱研究所の全創作タイトルを、各タイトルのストーリーを「イベントストーリー（章）」として踏まえたうえで一つに束ねる**買い切り型クロスオーバーRPG**。運営型（ソシャゲ）を避け、以下の二層で展開する。

- **Phase A: TRPGシステム＋シナリオモジュール集**（同人頒布・運営コストゼロ）
- **Phase B: Unity製オムニバスRPG**（買い切り＋章別無料アップデート）

Phase A のモジュールが Phase B の脚本・バランス検証を兼ねる。

### 世界観上の正当化（既存設定のみで成立）

| 候補 | 内容 | 根拠 |
|---|---|---|
| A. メタ層フレーム | フィジカル9／超次元執筆空間（アトリエ）が「第8界の記録を巡る」枠物語 | `Works_DestinyFoxRecords/References/ref_Vocabulary.json` |
| B. 作中作 | ユニバイト・ユニバース上の「コードインフィニティ」製ゲームという体裁 | `Works_UnibyteLive/References/ref_Vocabulary.json` |

→ **推奨は A を主、B を演出（UI・メニューをメタバース風にする等）として併用**。どちらを採るかは User 決定事項（§8）。

## 2. 先行事例分析: アークナイツ／アークナイツ：エンドフィールド（GRYPHLINE）

参照理由: 多数の陣営・地域を抱える共通舞台設定（テラ）を、章単位のフィーチャー構造と陣営演出で破綻なく積み上げている先行例。エンドフィールドは同一世界の別時代（約100年後）・別大陸（タロII）に独立した進入点を作る手法の実例（2026-01-22 サービス開始、3Dリアルタイム戦略RPG）。

採用する設計文法（→ 本企画への写像）:

| # | アークナイツ側の文法 | 本企画への写像 |
|---|---|---|
| P1 | **メイン軸＋サイドストーリーの二層**。イベントは特定陣営・地域を深掘りし、後に恒常化されて新規でも追える | メイン軸＝WDC/WDP 年表（第7〜第9創世紀）。各タイトル＝サイドストーリー章。TRPGモジュール（Phase A）→ RPG章（Phase B）への「恒常化」に置換 |
| P2 | **章＝陣営フィーチャー**。UI色・ロゴ・BGM・敵勢力を章ごとに切替、陣営ビジュアルアイデンティティが強い | `dict_Faction`（31組織）＋各作品の `CalendarColorId`・`ColorPalette` を章テーマカラー／陣営ロゴに直結。章突入時にタイトルロゴ演出 |
| P3 | **重厚な世界観資料**（ゲーム内辞典・用語集）が本編の省略を許す | 既存の創作DBサイトがそのまま「公式設定資料集」。ゲーム内辞典は DB の `References/ref_*.json` から抜粋生成（hideText はゲーム内でも伏字＝情報開示演出に転用） |
| P4 | **中立ハブ視点**（ロドス＝移動型拠点）が各陣営を「訪ねる」ことで章の独立性と連続性を両立 | ハブ拠点候補: 基底岐路 KERNEL-BRANCH（FL78・移動型拠点）／国際情報広報機関ミハイル（本拠なし・全域）／アトリエ（メタ層）。→ User 決定事項 |
| P5 | **エンドフィールド方式**: 同一世界の別時代・別大陸に独立進入点を置き、新規プレイヤーの入口とする | 獣爾騎兵（龍天国・2039-43・他タイトルと明示リンク0件）がこのポジションに最適。単独体験版／独立モジュールとして切り出し可能 |
| P6 | （反面教師）運営型ガチャ・限定復刻は個人サークルでは持続不可能 | リリース形態のみ置換: **買い切り＋章別無料アップデート**（Steam アーリーアクセス型）。ガチャの「収集欲」は ExistingRarity（UR〜C 9段階）を用いた**ゲーム内収集要素**（72IS素子・カード・ナンバー）で代替 |

## 3. 物語構成案

### メイン軸（縦糸）

`ref_Society.json` の創世期年表をそのまま背骨にする。

```
WDP.VII 多様化恐慌（〜2043）→ WDC.VIII 左遷可能社会（2044〜）
→ WDP.VIII 逆行恐慌（2044〜46）→（未回収の伏線）『第9の世界破壊』
```

- 共通敵: **財前小里／終藤こさと**（豹変系女子NW・『破壊主』代理人）。「夜月機関・運命線探偵・獣爾騎兵などへ牙を向く」と DB に明記済み（`ref_Society.json` / SCG `db_Primary.json`）。
- 最終章の題材: 『第9の世界破壊』。**現状どの作品DBにも年代・内容が紐づいていない空席** → 本ゲームのオリジナル最終章として使える唯一の枠。内容の確定は User の正典判断（§8）。

### 章マップ（横糸・時系列順）

| 章 | タイトル | 年代（西暦） | 舞台 | フィーチャー陣営 | 章固有メカニクス | 素材成熟度 |
|---|---|---|---|---|---|---|
| 序 | （フレーム）フィジカル9 | 時代軸外 | アトリエ | フィジカル9 | チュートリアル／章選択ハブ | 仮公開中心 |

| 5 | ナンバーテールズ | 2050–51 | 九蓮国 | 百花繚乱研究所 | 数秘加護・主従契約（バディ）・コアフォルダ変形 | ◎ 93体公開・最成熟 |

| 終 | 第9の世界破壊（新規） | 2053以降？ | 第8界全域 | 全陣営連合 vs 破壊主 | 全章メカニクスの統合 | — 完全新規 |

- **豹変系女子／桜花兄弟は「章」を持たない横断キャラ枠**とする（アークナイツにおける各国要人・敵幹部ポジション）。8方位×8徳の「罪 vs 徳」構造を、各章のゲスト出演＋最終章の対決軸として全編に散らす。両作の「各国放浪・各国所在」という設定と一致し、章を跨ぐ「顔つなぎ」役を公式設定のまま担える。
- 第2章と第3章（先代編）は年代が完全一致（2044–46、世界創造と世界破壊の表裏）。**同一事件を別視点で描く前後編**にすると、アークナイツのメイン章⇔サイドストーリー相互参照の快感を再現できる。
- 注: 各章の具体的なシナリオ本文は本書では書かない（未公開創作の自動生成禁止規約に従う）。章の器とメカニクスのみ提案。

### プレイ順の設計

素材成熟度順（NT→FL78→獣爾→…）と物語時系列（獣爾→FL78→…→NT）が逆転している。→ **エピソード選択式（ライブアライブ／オクトパストラベラー方式）**で章を順不同解放にすれば、開発順とリリース順を物語に縛られず決められる。序章（アトリエ）が章選択ハブを世界観的に正当化する。

## 5. Phase A: TRPGシステム＋シナリオモジュール集

- **形態**: オリジナル軽量システム（判定は 6軸×ランクの2d10 程度を想定）のルールブックPDF＋章別シナリオモジュール。BOOTH 頒布＋ココフォリア用素材（駒画像は既存 Images/VRM スクショを流用）。
- **モジュール＝章マップの1行**。1本目は素材が揃う「獣爾騎兵」（P5: 独立進入点・7キャラで卓が組みやすい）か「ナンバーテールズ」（最成熟）を推奨。
- hideText を秘匿ハンドアウトに、SafetyLevel を暴走表に、Relation を PC間関係表にそのまま変換。
- **役割**: 各章のプロット・NPC・戦闘バランスの実地検証。プレイレポは SNS 小出し公開の文化とも噛み合う。
- 副次創作ガイドライン（`guideline.md`）に「TRPGセッション・リプレイ動画」の扱いを追記する必要あり → User 決定事項。

## 6. Phase B: Unity製オムニバスRPG

- **開発環境**: Unity ＋ Claude Desktop（Cowork）の Unity MCP 連携。スクリプト生成・シーン構築・アセット検証をこのセッション系列から直接操作できるため、個人開発のボトルネック（実装量）を大幅圧縮できる。
- **ビュー**: 2D〜2.5D（HD-2D風）。VRM 資産（NT は `VRMs/` あり）を 3D 化に使うか、ドット絵に落とすかは章演出方針と合わせて決定。
- **戦闘**: 共通基盤（§4）のコマンド式 or 軽量タクティクス。章固有メカニクスは「章の間だけ追加されるサブシステム」として実装（ライブアライブ方式）。
- **リリース**: Steam＋BOOTH/itch.io、買い切り。アーリーアクセスで序章＋1章から開始し、章を無料アップデートで追加（P6）。章追加のタイミングを各タイトルの DB 公開（released 化）と同期させれば、「ゲームでの登場＝実質初公開」を公式の初出イベントとして演出できる。
- **辞典連携**: ゲーム内辞典は DB の JSON から自動生成（`Localization/` の対訳資産で日英同時対応も視野）。

## 9. リスク

- 桜花兄弟・ハンカクライブは DB 本文が骨格のみ → 該当章の前に DB 側の執筆が先行して必要（開発順を素材成熟度順にする理由）。
- 章別無料アップデートは「完成版を待つ」買い控えを生みやすい → 序章＋1章の時点で1本のRPGとして完結感を持たせる構成が必須（エンドフィールドが単体で完結して見せているのと同型）。
- Relation・ConversationPattern の充実度がタイトル間で極端に非対称（NT ◎／他はほぼ0）→ 絆システムは NT 章で最大化し、他章では控えめに設計。
