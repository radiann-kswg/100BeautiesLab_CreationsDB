# 2026-02-21 残留希望タスク

## 概要

2026年2月中に行ったリポジトリの全体整備を通し、これから実装対応タスクや、将来対応についてをまとめる。
また、優先順位として「最優先タスク」を先に着手し、続いて３つの規模それぞれで番号の優先順に「希望タスク」を実施する。

## 最優先タスク

### 1. トップページのMarkdown破綻の修正

GitHub Pagesのトップページで折りたたまれている箇所のMarkdownが破綻しているため、これを修正する。

### 2. トップページの誘導改善

[API本体](./api/)や[キャラシート生成機能本体のページ](./pages/character.html)がどこにあるかがわかりづらいので、これらのリンクを明確化する。GitHub Pagesのトップを`pages/character.html`とガイドラインへ視覚的に誘導する形式に変更する。（GitHub側の設定が必要ならuserに提案してもらう）

## 希望タスク（規模,優先順位順）

### 大規模

- 1. キャラシート生成で行っているマージ機能（和文・英文対応、参照解決など）をAPIから行うように改修。これにより、API利用を想定したデータベースの出力も保証され運用範囲が広がるため。（運用例：創作キャラクターのロールプレイを行うAIチャットボットの開発など）
- 2. API側が予約語として判断し機械的に処理する箇所の命名法則を改善（例：`_`をprefixにもつものは関数的処理・`$`もしくは`#`をprefixにもつものは宣言的処理を行うので予約語だが、`Images`は画像パス参照・`is(For)Secondary`は一次創作と二次創作の判別のためにあるもので API側の機械的な処理が必要なため本来は予約語になるはず）
- 3. 創作キャラクターの会話パターンに関する情報を追加（例：口調、話す内容の傾向、会話の頻度など）、ただし**この作業はGitHub Copilotによる自動生成をあくまでも補助の範囲で運用し、Userの手動入力を主体に行うことを想定**（理由：創作者の意図しない創作作品のデータを生成するリスクがあるため）

#### 将来的な展望

- APIのシステム構造がより強化されることで、JSONデータベースのどこがユーザ向けに改変可能な個所か・どこがAPIの機能に依存しているのかをより明確に区別できるようになり、ユーザがAPIの機能を活用してデータベースをより柔軟に運用できるようになることが期待される。
- プロフィール型ではなく会話型の情報も取り扱うことで、より多様な創作キャラクターの演出機能を提供できるようになる。また、生成精度を保証できれば創作者の執筆工数の削減につながる可能性もある。

### 中小規模

- 1. `db_type.json`で`$type: "#Index"`と型宣言されている場合、そのフィールドはデータベース大元の`db_meta.json`にある`$DefType_Index`と同型式なフィールドとして扱うように仕様追加（できれば、`NumberTales`の`Relation`フィールドなどで`Num`フィールドとキャラクター情報の照合ができるところまで）
- 2. 画像参照フィールドも`db_type.json`（と`db_meta.json`）からDBフィールド名をハードコーディングせずに動作するよう仕様強化
- 3. 準二次創作DB(`db_SelfSecondary`)などのデータベース構造やタイトルを持たない二次創作についてもAPIが理解できる形に修繕（例：`sec_Category`からも`_Common`を参照可能にする）
- 4. 未着工の創作タイトルもデータベースの補完を開始（例：`Works_PastDivers`, `Works_UnauthedLogica`）、ただし**この作業はGitHub Copilotによる自動生成を前提とせず、Userが手動で行うことを想定**（理由：創作者の意図しない創作作品のデータを生成するリスクがあるため）

### 零細規模

- 1. DBフィールド名のタイポミスやJSON宣言箇所の不備がないか確認
- 2. API本体のドキュメントやガイドラインがわかりづらいので、第三者にも良識の範囲で運用しやすいように整備
