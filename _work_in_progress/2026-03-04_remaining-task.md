# 2026-03-04 希望タスク計画（提案）

## 目的

- 優先タスク（最優先1〜3）の完了後、添付の「希望タスク（規模,優先順位順）」を実装可能な単位に整理し、**全体の対応順（ロードマップ）**を提案する。
- 本ログは「何を先にやると安全か/戻しやすいか」を重視し、既存方針（スキーマ駆動・typedef 優先順位・テスト重視）に合わせる。

## 前提（このリポジトリの方針）

- スキーマ駆動（`db_type.json($DefType)` と `db_meta.json($VarsDef)` がソース・オブ・トゥルース）を最優先。
- typedef 駆動の優先順位は **表示分類 → 正規化 → 画像 → 検索**。
- 大規模更新は `npm test`（Vitest）での回帰確認を必須とする。
- 「創作内容の自動生成」につながるもの（会話パターン等）は **Copilot は補助**、基本は User 手動入力。

## 希望タスク一覧（整理）

### 大規模（優先順）

1. **UI 側で行っているマージ（JP/EN、参照解決など）を API 側へ寄せる**
   - 目的: API 出力の保証範囲を広げ、第三者利用（例: AIチャット等）に耐える形にする
   - 影響: `lib/data-common.js` / `lib/sw-common.js` / SW エンドポイント / テスト
   - リスク: 仕様の確定・互換維持・レスポンスサイズ増大

2. **API 予約語/機械処理対象の命名法則改善**
   - 目的: どこが「データとして自由に改変可能」かを明確化
   - 影響: typedef 仕様、予約語判定、ドキュメント
   - リスク: 既存データ/コード互換

3. **会話パターン情報の追加（口調等）**
   - 目的: 多様な演出機能
   - 前提: 自動生成は補助、User 手動主体
   - リスク: スキーマ増設と運用ルールの設計が必要

### 中小規模（優先順）

1. **`$type: "#Index"` の扱い拡張（`$DefType_Index` と同型として扱う）**
   - 目的: `Relation` 等の照合（`Num` 等）で UI/API が自然に扱えるように

2. **画像参照フィールドのスキーマ駆動強化（ハードコード削減）**
   - 目的: `db_type.json` / `db_meta.json` の定義から自動解決

3. **`db_SelfSecondary` 等の構造・タイトル無し二次創作を API が理解できる形へ修繕**
   - 目的: DB 種別の多様性に耐える

4. **未着工タイトル（例: `Works_PastDivers` 等）の DB 補完開始**
   - 前提: Copilot 自動生成前提にしない（User 手動）

### 零細規模（優先順）

1. **DB フィールド名の typo/JSON 宣言不備チェック**
2. **API/ガイドライン/ドキュメントの整備（第三者に分かりやすく）**
