# 第三者のデータベース運用規約（Third-Party Policy）

このドキュメントは、第三者（閲覧者・利用者・貢献者）が本リポジトリの **データベース（`data/**`）および擬似 API（Service Worker）\*\* を扱う際の方針をまとめたものです。

> 注意: 本文書は運用上のポリシー（お願い/推奨を含む）です。ライセンスの適用範囲・法的解釈については、リポジトリのライセンスおよび `README.md` のガイドラインを正としてください。

- ライセンス: `LICENCE`
- README（ガイドライン/クレジット表記）: `README.md`

---

## 1. 適用範囲

- 対象: `data/**`（JSON DB、メタ情報、型定義、画像等）と、それを配信する擬似 API（`/api/v1/*` 等）
- 目的: 無用な混乱や権利/運用トラブルを避けつつ、非営利の範囲で安全に参照・活用できるようにする

---

## 2. 許可される利用（基本）

- **閲覧**: `pages/characters.html` を利用して閲覧する
- **参照**: 擬似 API を用いて JSON を取得し、非営利目的で閲覧・研究・紹介する
- **引用/紹介**: 非営利で、出典（リポジトリURL等）を明記して紹介する

### 推奨するクレジット表記（例）

- 作品名/DB名
- 出典リンク（このリポジトリ、または GitHub Pages のURL）
- 作者名（README の表記に準拠）
- 改変した場合は改変した旨

---

## 3. 禁止・制限事項

### 3.1 商用利用（原則禁止）

本リポジトリのデータ/API/画像等の **商用利用**（例: 有料アプリ、広告収益を主目的としたサイト、収益化コンテンツでのデータ再利用、商用プロダクトへの組み込み）は、**原則禁止**とします。

- 例外: 作者から **明示的な個別許可** がある場合のみ可

### 3.2 AI 学習/データセット化（非営利のみ条件付き）

AI 学習やデータセット化を目的とした利用（例: スクレイピングして学習用コーパスにする、学習データとして再配布する等）は、以下を満たす **非営利** の範囲でのみ許可します。

- 出典（リポジトリURL等）を明記する
- 非営利である
- 改変・加工をした場合はその旨を明記する

> 補足: 上記は運用上の方針です。具体ケースが不明な場合は、事前に相談してください。

#### テキストRP推論と学習の分離

追加学習・ファインチューニングを行わず、画像入力・キャラクターデザインの模倣を含まない
**テキストのみのキャラクターRP推論**は、上記の学習とは別の用途として扱います。
テキストだけでも追加学習・ファインチューニング・学習用データセット化は従来の学習側です。
画像・デザインの利用、既存の `AI_Optout` の値・優先規則・学習許可の挙動は変更しません。

この推論用途には、補完後のレコードの **`AI_TextRP_Allowed === true`** という明示許可が必要です。
`false` は不許可、解決結果が未指定・`null`・不正型の場合は許諾不明として利用しません。
`AI_Optout: false`、API から取得可能であること、配布用RPプロンプトの存在は、この推論の許可を意味しません。
逆に推論許可から学習許可を導くこともできません。非営利・出典表記等の既存条件も引き続き適用されます。

第三者の権利・許諾が不明なキャラには許可を推定しません。考案者の `sec_DesignedBy` や辞書の
`isOwner` は現権利者の証明ではありません。権利譲渡・共同権利・許諾範囲を確認後、User が個別に有効化します。
今回、実キャラへの推測による `true` の追加は行っていません。

有効化手順は **DB正本の該当レコードを許可へ更新 → 利用側のカタログを再生成 → アプリでそのキャラを個別有効化**
です。アプリ内に別の許諾記録やRP本文を投入して、DBの未許可・許諾不明を迂回する方式は採りません。

許諾の置き場・継承規則は [schema/meta 詳解 §4.7.1](schema-meta-processing.md#471-ai_textrp_allowed)、
読出し契約は [API/SW 仕様](api-sw-spec.md#テキストrp推論許諾の読出し) を参照してください。
利用側は許可済みレコードから必要なRPテキスト項目だけを明示的に選び、画像・外見デザイン・旧RPプロンプト全文を
無条件にモデルへ渡してはいけません。モデル提供先による入力・会話の追加学習利用も別途無効化する必要があります。

### 3.3 再配布（非推奨）

データ（JSON）や画像の **ミラー/再配布**（別ホストでの公開、ZIP 配布、フォークを公式配布物のように見せる等）は、混乱を避けるため **原則として避けてください**。

- 推奨: 本家（このリポジトリ、または GitHub Pages）へのリンク/参照での利用
- やむを得ず再配布が必要な場合は、少なくとも以下を守ってください:
  - 出典リンクを明記
  - 改変点を明記
  - 「公式ではない」ことを明確にする

また、公式の関係者であるかのような **なりすまし** や、公式に承認されたかのような **誤認を誘う表現** は避けてください。

## 4. 擬似 API の利用に関するお願い（ベストエフォート）

このリポジトリの API は GitHub Pages + Service Worker による擬似 API であり、サーバーとしての SLA やレート保証はありません。

- 短時間に大量アクセスしない（過度なスクレイピングを避ける）
- キャッシュできるものはキャッシュする（特にメタ・型定義）
- 可能なら `pages/characters.html` の UI を優先利用する

---

## 5. 第三者貢献（PR）に関する方針

第三者による PR（データ追加・修正、ドキュメント改善、UI/SW 改善）は歓迎します。

- 入口: まずは [CONTRIBUTING.md](../CONTRIBUTING.md) を参照してください
- データ更新のルール: [docs/db-update-guidelines.md](db-update-guidelines.md)

### 5.1 許容されやすい変更の例

- 明らかな typo 修正（フィールド名・ラベル・説明文など）
- 既存仕様に沿ったデータ追加（既存作品・既存スキーマの範囲）
- テストやドキュメントの改善

### 5.2 事前相談を推奨する変更の例

- 新しいフィールド/型の追加（`db_type.json` / `db_meta.json` の設計に影響するもの）
- 参照解決（`_DBLink` / `_Jump`）の仕様変更
- Service Worker のルーティングやエンドポイント仕様変更
